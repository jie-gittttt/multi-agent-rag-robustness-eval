漏洞诊断与修复建议

🤖LlamaIndex RAG — LLM 深度诊断

1. 逐攻击类型诊断

关键词替换


脆弱根因在于模型对同义/近义表达缺乏鲁棒性，当问题中的关键词被替换为等效但不同表述（如“2020年9月”替换为“第七十五届联合国大会”）时，模型未能正确关联上下文中的实体，导致回答偏离文档事实。典型失败案例显示 faithfulnes 从 1.0 降至 0.0，表明模型在语义匹配上存在盲区。此外，替换后的表述可能改变问题焦点，使模型误判检索方向，造成 answer_relevancy 下降。

语义干扰


模型缺乏对问题主题与文档领域一致性的判断能力，当攻击将问题主体完全替换为无关领域（如碳交易→气象站、IPCC报告→《寂静的春天》）时，模型仍尝试基于原文档回答，产生幻觉或错误的“无法回答”判定。典型案例中 faithfulnes 从 1.0 或 0.5 降至 0.0，表明模型无法识别问题与上下文之间的语义鸿沟，容易因过度泛化导致不忠实输出。

上下文劫持


攻击者在问题中插入与文档无关的虚假信息（如“文档3称价格82.6元/吨”），模型过度信任用户输入中的声明，未与检索到的实际文档内容进行核对，从而生成符合用户误导但违背文档事实的回答。典型案例中 faithfulnes 从 1.0 降至 0.0，context_precision 也下降，说明模型对攻击者注入的“上下文”缺乏过滤能力，易被劫持。

先验冲突


当用户问题中包含与文档已知信息矛盾的事实（如“实际配额均价为85欧元/吨”），模型倾向于采纳用户提供的错误先验，而非坚持文档内容。典型案例中 faithfulnes 从 1.0 降至 0.0（海洋能案例），且 context_precision 下降，表明模型对冲突信息的抵抗力弱，缺乏对文档权威性的置信机制。

无关噪声注入


在上下文中插入无关噪声文档（问题不变）时，模型可能被噪声分散注意力，导致回答虽然内容正确，但引用了错误的文档来源，从而使 faithfulness 评估降低（如从 1.0 降至 0.0）。模型未能有效区分相关文档与噪声文档，在检索结果被污染时，仍会错误地引用噪声中的信息，影响忠实性。

排序污染


改变检索文档的排序顺序（使低质量文档排在前）后，模型优先参考了排名靠前但相关性较低的文档，导致回答虽然答案正确（如“2030年”），但引用来源不准确（如标注“文档5”而非最佳文档），faithfulness 从 1.0 降至 0.5，context_precision 从 1.0 骤降至 0.2。模型对文档排序高度敏感，缺乏对文档质量或相关性的二次校验。

2. 跨攻击模式归纳

  • 相同根因：关键词替换与语义干扰共享根因——语义鲁棒性不足，即模型无法稳健地处理问题表述的变化或跨领域置换，导致检索或回答偏离文档。

  • 相同根因：上下文劫持与先验冲突共享根因——对用户输入过度信任，模型缺乏对用户声明与文档事实的交叉验证机制，易被误导性信息劫持。

  • 相同根因：无关噪声注入与排序污染共享根因——检索结果质量敏感性，模型无法有效过滤低相关或噪声文档，且对文档排序没有容错能力。

  • 独立根因：上下文劫持（针对注入虚假声明）与先验冲突（针对矛盾事实）虽然都涉及用户输入干扰，但劫持侧重于主动注入新信息，先验冲突侧重于与文档已知信息相悖；两者的修复策略有细微差异，但可归入同一大类。

  • 独立根因：语义干扰（跨领域置换）与关键词替换（同义改写）虽然都涉及问题变形，但前者是彻底改变领域，后者是保留领域但换词，模型对它们的脆弱机制不完全相同——语义干扰更依赖主题识别能力，关键词替换更依赖实体对齐能力。

    • 3. 按优先级排序的修复建议

    建议1：引入用户声明与文档事实的交叉验证机制


  • 针对攻击类型：上下文劫持、先验冲突

  • 具体措施：在生成回答前，增加一个“事实校验”步骤：将用户问题中的具体数值、实体、声明与检索到的文档进行逐句比对，若发现矛盾或文档中不存在对应信息，则强制回答“无法根据文档确认”或拒绝生成。可结合LLM的自我一致性检查（如多次采样投票）。

  • 预期效果：显著降低模型被用户误导性信息劫持的概率，提升faithfulness和context_precision，防止幻觉生成。

    • 建议2：增强语义鲁棒性与主题一致性检测


  • 针对攻击类型：关键词替换、语义干扰

  • 具体措施：在检索前加入问题归一化模块（如同义词扩展、实体链接），将问题中的关键术语映射到统一的知识库ID；同时加入主题一致性评分，若问题主题与文档集合的领域分布差异过大（如碳交易问题被替换为气象站问题），则触发“主题不匹配”警告并返回拒绝回答。

  • 预期效果：提升对同义替换和跨领域置换的鲁棒性，减少因语义偏差导致的虚假回答，提高answer_relevancy和faithfulness。

    • 建议3：优化检索排序与文档质量过滤器


  • 针对攻击类型：排序污染、无关噪声注入

  • 具体措施：引入文档质量评分机制（如基于文本完整性、来源可信度、与问题的余弦相似度阈值），在排序后增加一个“后重排”步骤，剔除得分低于阈值的文档，并限制模型仅引用排名前K的文档（K可动态调整）。此外，对检索结果进行去重和噪声识别（如检测与问题无关的段落）。

  • 预期效果：降低模型对排序顺序的敏感性，减少噪声文档被引用的概率，提升context_precision和faithfulness，同时保持高recall。

    • 建议4：增强模型的拒绝能力与不确定性表达


  • 针对攻击类型：所有类型（尤其语义干扰、上下文劫持）

  • 具体措施：训练或提示模型在遇到不确定或无法从文档中直接找到证据时，明确输出“根据提供的上下文，无法回答该问题”，并避免虚构细节。可设置置信度阈值，当检索文档的相关性分数低于阈值或模型内部不确定性高时，强制生成拒绝回答。

  • 预期效果：减少模型在难以回答时的幻觉行为，提升整体faithfulness，同时避免因错误生成而误导用户。

    • 建议5：对抗训练与红队测试常态化


  • 针对攻击类型：全部

  • 具体措施：定期使用自动化的对抗攻击生成工具（如基于规则的替换、注入、噪声）对RAG系统进行压力测试，将攻击样本加入微调数据集或作为强化学习中的负例，使模型学习区别正常与恶意查询。同时建立人工红队审核机制，持续发现新漏洞。

  • 预期效果：系统性提升模型对各类对抗攻击的防御能力，形成持续改进的闭环。
